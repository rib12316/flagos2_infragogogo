# KV 量化方向 · 完整负结果报告（2026-11-02/03）

> 方向 A（KV int8/fp8 per-token-head 量化）经系统性实验后**终判不可行于 BI-V150**。
> 8+4 个受控实验的完整矩阵、根因分析与结论如下——本报告即技术报告素材，防止后续重复投入。

## 实验矩阵（math_500 L3 limit32，max_tokens 8192）

### int8_per_token_head（精度维度）

| 配置 | 分数 | 备注 |
|---|---|---|
| bf16 + 图 3D（基线对照） | **93.75%** | |
| int8 + eager 3D | **90.62%** | 量化本身损失 ~1 题噪声级 |
| int8 + 图 3D（上游） | 75.0% | 图模式崩 |
| int8 + 图 3D + no-fill patch | 78.12% | fill 修复仅 +1 题 |

| int8 + 图 2D + 大预热(256请求) | 84.38% | 部分恢复（编译热身混淆） |
| int8 + 图 3D + 大预热 | 71.88% | **预热救不了 3D → 图模式确定性坏** |

上游 kernel 单测（`tests/quantization/test_per_token_kv_cache.py`）56 全过 → kernel eager 语义正确；
bug 在**图 replay 集成**（已排除：fill 录制、prefix caching、3D 特异性、冷启动/dummy 污染）。
错误模式：推理链格式正常但细节算错（非乱码）→ 细微数值偏移。

## 根因分析

1. **BI-V150 无量化 KV 硬件加速**：fp8 KV 读字节减半未兑现加速——attention 带宽利用率本为 76%（非纯带宽受限），scale load（每 token-head 4B）+ fp8→bf16 dequant 的开销抵消读减半收益，kernel 反慢 4-10%。
2. **prefill 量化写入 + fp8 attention 读**使 prefill 峰值吞吐 -25%；16K 场景 88% token 是 prefill → prefill 损失压倒 decode 的 7× 容量收益。
3. int8 分支存在图 replay 数值偏移 bug（上游 fork 私有功能，图路径未被测试覆盖）。

## 结论与资产

- **量化方向关闭**：两 dtype 均不可行（int8 精度崩 / fp8 性能崩），除非未来拿到图 bug 的上游修复 + 量化访存硬件支持
- 分支 `feat/kv-int8-quant` 保留全部 patch（scale-cache capture-safe、2D debug 开关）与 12 份实验数据
- **方法论沉淀**：① limit32 快速评测须控制预热状态（冷启动截断可伪装成 -30% 精度损失）；② 图模式专属 bug 的二分法（eager 对照 → 路径开关 → 预热控制）有效但昂贵（本次 ~8h）
- 转向：B1（TD 终判）后收尾，剩余算力投沐曦侧（只做天数=放弃一半性能分）
